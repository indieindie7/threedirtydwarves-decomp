Sega Saturn game Three Dirty Dwarves (Appaloosa Interactive for Sega, US T-30401H V1.011, 1996; SH-2 code, GNU or Hitachi SHC; Hungarian developers, file names are Hungarian: keret = frame, kuka = bin, zsaru = cop, lada = crate, taku = cab, rud = rod, tuske = spike, lampa = lamp, bumm = explosion). Research only. Game: side-scrolling beat-em-up; three dwarves (Taconic with a baseball bat, Corthag with a shotgun, Greg with bowling balls) switch on the fly, with hit points shared by a dwarf roster; enemies: punks, cops, orcs, taxis; props: bins, crates, spikes; 15 stages plus map, intro, logo, secret; sprite packs A_*.BIN (actors), B_*.BIN (props), VDP2 scroll maps, PCM sound. This is the Windows 95 PC port DWARF.EXE (x86 PE, MSVC 4.x, linker 3.10, 1996-12; DirectDraw, DirectSound, DISPDIB, LZ32, winmm). It is the community speed-fix copy: an added 167-byte section .Silvana imports fps.dll (ignore that hook; the rest is the original exe). Many functions are the MSVC C runtime (name them with their plain CRT names: malloc, fopen, _flsbuf, strlen, __sbh_*, etc.). PC data files: common/tddlow.pwh/.pwd, A_*.pwd/.pwh sprite packs, stage<n>/b_map<nn>.plh/.pln maps, demo/stage<n>.dem demos, .sdh/.sdp sound, .blh/.blk, .ach/.act. Focus names on file loading, sprite pack decoding, DirectDraw surface and palette setup, DirectSound mixing, input, dwarf state machine, enemy AI, collision, camera scroll, menus.
Evidence to use: strings, called functions (imports and names given by earlier slices), Win32/DirectX API usage, how the function uses its arguments. Values like 0x12345678 in a decompile may be data pointers.

Task: name functions from the Ghidra decompile. FILE holds the decompile of a slice of the functions of DWARF.EXE. Name EVERY function in FILE whose name is still FUN_xxxxxxxx (skip ones that already have a name).

Naming style: lowercase module prefix + CamelCase verb, e.g. vdp1_ClearCommands, cd_ReadSectors, pad_ReadDigital, car_UpdatePhysics, menu_DrawCursor, math_FixedMul, mem_Copy. C runtime copies: memcpy/memset/strcpy/sprintf etc. with plain names. Tiny stubs that only return: stub_<addr>. When unsure, still give the best descriptive name and add "provisional" at the start of the comment.

Output: write lines to OUT (create it with Write; one line per function, no other text):
0x<addr> func <name> hand <comment of 5-20 words: what it does, key callees, registers or strings>
Addresses as 8 lowercase hex digits (e.g. 0x06012a3c). Names must be unique within OUT; append _2, _3 when two functions would share a name. Do not read files other than FILE. Read FILE in pieces (offset/limit, about 600 lines at a time) until the end. Reply at the end with only the line count.
